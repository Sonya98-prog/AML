# AML Академия — платформа обучения по COMITA AML

Корпоративная обучающая платформа АО «Комита»: курс для продуктовых аналитиков и РП по системе COMITA AML — домен ПОД/ФТ, 115-ФЗ, 11 функциональных компонентов, ЭДО с регуляторами, лицензирование и миграция.

Статическая версия: сайт публикуется на **GitHub Pages** автоматически при каждом `git push`. Вход не нужен; личный прогресс (зачёты, результаты тестов) сохраняется в браузере ученика.

## Возможности

- **18 занятий в 7 блоках** — концепция, схемы, разбор кейсов, 78 вопросов практики с фидбеком, мини-проверки блоков (порог 70%)
- **Личный прогресс без регистрации** — отметки о зачёте и результаты тестов хранятся в localStorage браузера и переживают перезагрузку
- **Глоссарий 53 термина** с поиском
- **Варианты ответов перемешиваются** при каждой попытке
- **Работает с телефона** — по той же ссылке

## Технологии

Next.js 16 (App Router, static export) · TypeScript · Tailwind CSS 4 · shadcn/ui · GitHub Actions для автопубликации

## Быстрый старт (VS Code)

Нужен Node.js 20+ или [Bun](https://bun.sh).

```bash
# 1. Установить зависимости
bun install        # или: npm install

# 2. Запустить в режиме разработки
bun run dev        # или: npm run dev
```

Откройте http://localhost:3000

## Публикация на GitHub Pages (уже настроено)

В репозитории лежит workflow `.github/workflows/deploy-pages.yml`: каждый push в `main` автоматически собирает сайт и публикует его.

**Разовая настройка** (если ещё не сделана): на GitHub откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.

После пуша подождите 2–3 минуты (вкладка **Actions** — зелёная галочка) и откройте:

```
https://<ваш-логин>.github.io/<имя-репозитория>/
```

## Локальная проверка статической сборки

```bash
STATIC_EXPORT=1 bun run build   # соберёт сайт в папку out/
```

(На Windows проще доверить сборку GitHub Actions — она запускается сама при пуше.)

## Где что лежит

| Путь | Что это |
|---|---|
| `src/content/course-data.json` | **Весь контент курса**: блоки, уроки, кейсы, вопросы, схемы (SVG), глоссарий, источники |
| `src/lib/course.ts` | Типы контента и правила (пороги зачёта, порядок уроков) |
| `src/lib/progress-store.ts` | Хранение личного прогресса (localStorage браузера) |
| `src/app/page.tsx` | Дашборд участника |
| `src/app/lesson/[id]/` | Страница занятия |
| `.github/workflows/deploy-pages.yml` | Автосборка и публикация на GitHub Pages |
| `next.config.ts` | Настройки: basePath `/AML` включается при `STATIC_EXPORT=1` |

### Как отредактировать урок

Откройте `src/content/course-data.json` и найдите урок по `id` (например, `"2.2"`). Внутри: `concept` (абзацы, таблицы, списки, коллауты, схемы), `case` (кейс), `practice` (вопросы: текст, варианты, фидбек `fb`, флаг правильного `ok`), `summary` (запомнить), `isCheck` (мини-проверка блока). После правки: commit → push — сайт обновится сам через 2–3 минуты.

## Важно знать о прогрессе

Прогресс хранится в браузере (`localStorage`) на устройстве ученика: на другом компьютере или в другом браузере список зачтённых будет пустым — это нормально для статической версии. Централизованный учёт всей команды (дашборд ментора) — в серверной версии платформы; её код сохранён в истории git и может быть возвращён при переезде на VPS (`scripts/deploy-vps.sh`).
